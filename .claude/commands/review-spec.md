`specs/` 폴더의 spec을 팀장 입장에서 비판적으로 검토한다. $ARGUMENTS

**파일은 고치지 말고 문제 목록만 출력한다.** 항목마다 파일·섹션 위치와 고칠 방향을 한 줄로 적는다.

점검 항목:

1. 4시간 안에 하기 어려운 기능
2. 모호한 계약 (필드 이름·타입·단위·null 여부가 불명확, 두 역할이 다르게 해석할 수 있는 것)
3. 두 역할이 같은 파일을 고치는 지점 (공용 파일을 A가 아닌 역할이 고치는 경우 포함)
4. 확인 불가능한 단계 (✅ 확인 방법이 없거나 막연한 것)
5. 빠진 실패 대비 (AI·DB 실패 시 기본 응답, 15분 막히면 대안 누락)

마지막에 가장 먼저 고쳐야 할 3개를 고른다.
